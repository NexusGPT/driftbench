# Protocol-excluded broad implementation experiment

Both executors start at 0/334 and implement all fourteen missing APIs together.
Each actual first repair reaches 334/334. The dispatch phrase “full cohesive
repair” was interpreted as replacing every stub. This bundles independent
capabilities and violates section 10’s one-cause-per-round protocol. These
observations are preserved, not reconstructed into a fictional sequence of
repairs, and contribute nothing to the causal pilot forecast.

The builder starts an unchanged second verification before receiving the stop.
It writes full feedback before process termination; its own notes distinguish
that artifact from successful process completion. Only completed rounds zero
and one are copied here. The blind executor has no second verification.

Fresh executors restart from identical untouched stubs with an explicit rule:
choose one observed cause, write its failing test, implement that complete
capability, measure, then select the next cause. Unrelated API stubs stay
untouched until selected; a single algorithm is never split into fake stages.
