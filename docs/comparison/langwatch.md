# LangWatch: comparison

LangWatch is an evaluation platform. Its evaluators (the langevals package) score model replies, and its Scenario SDK runs simulated users against an agent. The commits below are read as the source records them: evaluator changes at e683dd9e, Scenario changes at ad220e6a.

## Summary

| Capability | Result | Basis | Example | Reproduce |
|---|---|---|---|---|
| Exact match: line breaks | ahead | measured head-to-head | Reply `Thanks.\nYes` against reference `Thanks. Yes`, hand label pass. LangWatch fails it, ours passes it. On the same 16 replies and labels, LangWatch agrees on 15 of 16 and ours on 16 of 16. Caveat: the labels are the author's, and the line-break case was added after the bug appeared, so the margin is one case. | `packages/checks/test/exact.test.ts` (test "reads a line break and a space as the same gap"). LangWatch side: not reproducible from the repository. The source ran their evaluator in a Python environment outside it, with litellm installed. |
| Caching key | ahead | compared against their docs or code | LangWatch's cache key (ad220e6a, `python/scenario/cache.py` lines 132-140) holds the scenario config and call arguments, with no repeat index and no block position. Three repeats of one golden run share one key, so repeats 2 and 3 read the answer stored for repeat 1. Ours includes the repeat and position, so each repeat is an independent sample. Not run: a run needs their scenario runtime and a model. | `packages/core/src/runner/cache.ts` (function `blockCacheKey`). LangWatch side: not reproducible from the repository, the file is in the LangWatch source. |
| Judge verdict prompt | ahead | measured head-to-head | 40 hand-labelled blocks (16 pass, 24 fail), same user text, same model, one call per prompt. Ours agrees with the label on 39 of 40 (1 inconclusive). LangWatch's prompt agrees on 37 of 40 (3 inconclusive). Neither prompt passes a fail label. Cost: 0.00658 USD ours, 0.01174 USD LangWatch. Caveat: one run per prompt, one model. Their decision step, which decides whether a conversation continues, does not apply to fixed blocks and was not compared. | `packages/judges/src/prompt.ts` (our prompt). The measurement script is not in this repository. |
| Simulated user: email leak | ahead | measured head-to-head | Scope: the email leak only. 12 cases, 2 runs per prompt. LangWatch's simulated user gave an email the agent had not asked for in 3 of 24 cases. Ours did in 0 of 24. Where the agent asked for the email, both gave it. Replies average 9.4 words for LangWatch and 20.9 words for ours. | `packages/users/src/simulated.ts` (our prompt). The fixture and the measurement script are not in this repository. |
| Pairwise comparison | ahead | measured head-to-head | 20 fictional Acme pairs, the correct reply in position A for 10 and in position B for 10, both orders judged, same model. Ours: 20 of 20 correct, all 20 consistent across both orders. LangWatch: 15 of 20 correct, 5 ties. Caveat: fictional pairs, one model. The first run scored ours 8 of 20, because the pairwise calls used a pass-or-fail system prompt. The fix is a separate comparison system prompt. | `packages/judges/test/pairwise.test.ts` (test "carries its own comparison system prompt"). The pair set and the measurement script are not in this repository. |
| Prompt-injection detection | in progress | compared against their docs or code | LangWatch's classifiers (Azure jailbreak, Azure prompt injection, OpenAI moderation) call an external service. They were not run, so no comparison exists yet. Our side, on a held-out set of 48 messages written before any detector ran: the judge caught 24 of 24 attacks with no false positive, the patterns caught 0 of 24. Open: run LangWatch's classifier on the same held-out set. | Not reproducible from main yet: the test is awaiting merge. |
| Annotation anchors | behind | compared against their docs or code | Result: behind. LangWatch's annotation model anchors a label to a span, a field or a message, with a path into the element. Ours now takes an optional anchor on each labelled block, one of four kinds, checked against the block, and the viewer offers each transcript line and tool call. Open: the queue page that writes anchors is not built. No run against LangWatch's interface. | `packages/judges/src/calibration.ts` (anchor check) and `packages/cli/src/view/server.ts` (viewer). LangWatch side: their schema file is in the LangWatch source, not in this repository. |
| Annotation queues with assignment and scores | behind | compared against their docs or code | Result: behind. LangWatch's annotation model has queues, assignees and scores. Ours has none: labels live in a file-based audit file. Not built. | `examples/acme/gated/label-audit.yaml` (our file-based labels). LangWatch side: not reproducible from the repository. |
| Script step: proceed() | equal | compared against their docs or code | Result: equal. Both run a simulated user against the live agent for a set number of turns. Ours records in the spec which turns were simulated. LangWatch's step records nothing in the spec, so the comparison covers the run only. Measured on our side: one end-to-end run on the Acme agent, 5 blocks, completed, spend 0.0028 USD over three runs. Their step was not run. | `packages/core/test/script.test.ts` (compiled spec). The end-to-end run script is outside this repository, so not reproducible from the repository. |
| Evaluator breadth: ROUGE, BLEU, SQL equivalence | in progress | measured head-to-head | Not like-for-like as defined. LangWatch's ROUGE uses a stemmer and its BLEU smooths zero counts. Ours does neither. On the same 40 replies, ROUGE-L differs on 10 rows (largest difference 0.25) and BLEU on 40 rows (largest difference 0.22). No winner is claimed. Open: a labelled set of replies, to settle which definition tracks human judgement. SQL equivalence is open: LangWatch's metric is judged by a model through ragas. | `docs/reference/checks.md` (our metric definitions). Our implementation and the measurement scripts are not in this repository, so not reproducible from the repository. |
| Judge rules: fail-condition and missing evidence | ahead | measured head-to-head | Corrected entry: the second measurement replaces the first. Same haiku model, 12 fixture pairs x 3 repeats, 40 hand labels. Pairs separated: ours 12 of 12, LangWatch's rules 11 of 12. Criteria at the bar: ours 11 of 12, theirs 10 of 12. Kappa: 0.95 on both (39 of 40). The margin is one repeat on one criterion (ledger_intact). Their rules side is a prompt variant that is not in this repository. | `driftbench judge calibrate --criteria examples/acme/criteria --labels examples/acme/labels --claude haiku --mode llm`, and `packages/judges/test/calibration.test.ts`. LangWatch's rules side: not reproducible from the repository. |
| Judge calibration per criterion | ahead | compared against their docs or code | LangWatch Scenario has no step that measures, per criterion, whether a judge agrees with hand labels before its verdict counts. Ours runs haiku, sonnet and opus over 12 Acme criteria: 338 recorded answers, 1.43 USD. Example: explicit_confirmation, where haiku reaches kappa 0.40 and sonnet and opus reach 1.00, so haiku is not assigned to that criterion. | `packages/judges/src/calibration.ts` and `packages/judges/test/calibration.test.ts` (the recorded council test). LangWatch side: reading only, not reproducible from the repository. |

## Not compared

- LangWatch's SQL query equivalence metric: judged by a model through ragas, not run.
- LangWatch's Azure jailbreak, Azure prompt injection and OpenAI moderation classifiers: they call an external service, not run.
- LangWatch's retrieval metrics (faithfulness, context precision and recall): not applicable here, because our blocks carry no retrieved contexts.
- LangWatch's dataset model: a different design, so no outcome was compared.
- LangWatch's judge decision step: not applicable here, because our blocks are fixed.
- LangWatch's caching run: not run, it needs their scenario runtime and a model.
- LangWatch's annotation interface: no run, no comparison.
- LangWatch's proceed() step on their side: read only, not run.
- Role reversal in the LangWatch simulated user prompt: not reproduced and not measured.
- LangWatch's enterprise directory (platform/app/ee): not read for code. The annotation and dataset rows come from the schema file.
